# 四轨终端音游

Bash 实现游戏和谱面编辑器，支持四轨单点、简单双押、首尾判定长条、音乐同步、谱面保存和试听。
保留无音乐练习模式。音乐通过 Python 标准库桥接 mpv JSON IPC，无需 pip 依赖。

## 启动

需要 Linux、Bash 5+、ANSI 交互终端。游戏窗口至少 **56 列 × 28 行**，编辑器至少 **76 列 × 28 行**。
游戏启动时按窗口高度扩大下落区域：28 行窗口使用 16 行下落区域，48 行窗口使用 36 行，
72 行窗口使用 60 行。可先最大化终端或缩小终端字体，再启动游戏，以获得更细的音符移动。
区域高度在启动时确定，调整窗口后请重新启动。
音乐播放和试听需要 **mpv 与 Python 3**。Ubuntu / Debian 可以安装：

```bash
sudo apt install mpv python3
```

直接运行 `./game.sh` 进入选歌与难度主界面，也可使用自己的谱面：

```bash
# 主界面：扫描 songs/ 下的 MIDI 歌曲
./game.sh

# 音乐谱面模式（请先准备自己的谱面和音频）
./game.sh songs/my-song/chart.csv

# 编辑或新建谱面（E 保存修改）
./editor.sh songs/my-song/chart.csv

# 无音乐练习 / 静音试玩指定谱面
./game.sh --practice
./game.sh songs/my-song/chart.csv --silent

# 游戏默认目标为 60 FPS，可按终端性能调整（15～120）
./game.sh --practice --fps 60
./game.sh --practice --fps 30
```

### 选歌、难度与最高分

把 `.mid` / `.midi` 文件放进 `songs/` 或其子目录，重新打开主界面即可选歌。
**W/S 或上下方向键**选歌，**A/D 或左右方向键**选难度，**H** 切换长条，
**Enter** 开始，**P** 进入无音乐练习，**Q** 退出主界面。歌曲较多时自动翻页。
默认选择半拍难度并开启长条，每次开始生成随机种子的谱面。结算或中途退出后，按任意键返回选歌。

| 难度 | 最小 grid | 独立最高分 |
| --- | --- | --- |
| Easy | `1`，整拍 | 一条 |
| Normal | `1/2`，半拍 | 一条 |
| Hard | `1/4`，四分之一拍 | 一条 |

主界面显示所选歌曲三档最高分，游戏中显示当前难度的历史最高分。
**完整打完**后才保存成绩，超过历史最高分时结算显示 `NEW BEST!`；中途退出、Ctrl+C 或播放失败不保存。
记录按 **MIDI 文件内容的 SHA-256 + 所选最小 grid** 区分，种子、选轨和长条开关不额外分榜，
静音完整游玩也会记分。同一 MIDI 改名或移动目录不会丢失记录，内容改变后视为另一首歌曲。
不同模式的音符总数可能不同，排行榜比较的是原始分数。

本地记录存放在项目的 `.local/scores/`，不会提交到 Git，也不随音频缓存清理而删除。
可用环境变量 `RHYTHM_SCORE_DIR` 指定其他目录。记录采用文件锁和原子替换，多个游戏同时结束也会保留较高分。
从 `random-play.sh` 或 `game.sh chart.csv` 启动同样会记录：谱面的音频须指向 MIDI，
难度优先读取 `# rhythm_grid=`；没有该头部的旧谱面按音符起点推断最细网格，
含非整拍、半拍、四分之一拍起点的旧谱面不加入这三档记录。编辑并保存谱面会保留已有 grid 头部。

```bash
# 固定随机种子 / 使用其他 MIDI 目录 / 调整主界面启动的游戏参数
./game.sh --menu --seed 42
./menu.sh --songs /path/to/midi --fps 30 --offset 50
./menu.sh --silent
```

游戏用 **D / F / J / K** 击打四条轨道，音符到达底部虚线时按键。**Q / Esc** 退出。
结束后显示分数、最大连击及判定统计。正常退出、Ctrl+C 或终止信号会停止播放器并恢复终端。
有音乐时，结束时间同时覆盖最后一个音符的判定时间和完整音频时长，尾奏播放结束后再结算；
自动选中的旋律轨道提前结束时，尾奏可能没有下落音符，但音乐会继续播放。静音模式仍按谱面长度结束。

| 判定 | 时间误差 | 分数 |
| --- | --- | --- |
| Perfect | ≤ 45 ms | 1000 |
| Great | ≤ 90 ms | 700 |
| Good | ≤ 140 ms | 300 |
| Miss | 超时未命中 | 0，连击清零 |

空按不扣分。单点建议短按，避免系统按键重复。
命中提示同时显示时间误差，例如 `PERFECT +12ms LATE`，正值表示判定记录偏晚，负值表示偏早。
至少命中 4 个音符后，结算会显示命中误差的中位数及本轮同步偏移，便于定位持续偏差。
如果跟随音乐敲击时误差持续约为 +60 ms，且当前 offset 为 0，可尝试 `--offset 60`；
若当前偏移非零，则在当前值上加上观察到的误差。该统计仅包含命中音符，不会自动修改谱面。

### 拍位置颜色与长条

游戏和编辑器按音符**起点**在 BPM 图中的拍位置着色：

| 起点位置 | 颜色 |
| --- | --- |
| 整数拍，例如第 5.000 拍 | 白色 |
| 半拍，例如第 5.500 拍 | 青色 |
| 四分之一拍，例如第 5.250 / 5.750 拍 | 黄色 |
| 其他拍内位置 | 紫色 |

颜色考虑变速点，允许整数毫秒存储产生的约 1 ms 舍入误差。长条的身体和尾部沿用起点颜色。

`[===]` 为头，竖线为身体，`[---]` 为尾；起点命中后判定线显示 `[HLD]`，等待尾部。
**终端长条采用起点、尾部各按一次的首尾判定。** 普通终端没有可靠的松键事件，
因此本版不检测提前松手，不要求一直物理按住。系统按键重复产生的字符也可能命中尾部，
但短条或多键同时按住时重复输入不可靠，建议按首尾两次来操作。
尾部到达判定线时按相同轨道键；过早的中途重复输入会被忽略。

头尾均使用 ±140 ms 判定窗口，成功后以两次误差中较差的一次决定 Perfect/Great/Good，
整根长条只计一个音符、一次分数和一次连击。漏掉头或尾记一次 Miss，不会重复扣分。
起点只进入待完成状态，完成尾部后才加分。相同轨道的长条与其他音符不能重叠，也不能共用结束时间点。
已有单点谱面保持原来的内容。MIDI 导入与随机生成默认仍为单点，加 `--holds` 可生成含长条的版本。

## 编辑自己的谱面

### MIDI 随机制谱并游玩

制谱由 Bash + awk 实现，使用系统自带的 `od` 读取 MIDI 字节，不需要 Python 或 `midicsv`。
需要 Bash 5+、awk 和 GNU coreutils（Linux 通常已自带）；音乐播放仍需 mpv 与 Python 3。

```bash
# 每次生成一个随机种子，制谱后直接开始游戏
./random-play.sh 'songs/saikoro - Far in the blue sky.mid'

# 用指定种子重玩同一张随机谱面
./random-play.sh 'songs/saikoro - Far in the blue sky.mid' --seed 20261106

# 只生成和保存，不开始游戏
./random-play.sh 'songs/saikoro - Far in the blue sky.mid' --seed 42 --generate-only

# 混合单点和长条；按起点拍位置自动显示颜色
./random-play.sh 'songs/Swan_song_–_Void.mid' --seed 42 --holds

# 从 MIDI 的半拍 / 四分之一拍范围抽取更多起音，形成更密的节奏
./random-play.sh 'songs/Swan_song_–_Void.mid' --seed 42 --grid 1/2 --holds
./random-play.sh 'songs/Swan_song_–_Void.mid' --seed 42 --grid 1/4 --holds
```

难度一致性针对**同一 MIDI、相同选轨、网格与长条设置**：保留简化谱面的全部起音时间和音符数量，随机变化轨道排列。
因此不同种子的时长、音符总数、每段密度和最短间隔完全相同。默认生成单点，头部按左右手交替排列，
每完整 8 个音符中四条轨道各出现两次，避免随机出密集同键连打或某一轨过多。
实际手感仍可能略有差异；这不是跨歌曲的统一难度评级。

颜色表示音符的**拍内位置**，不代表两个相邻音符之间的间隔。`--grid` 决定抽取密度：
`1`（默认）只允许整数拍起点，`1/2` 只允许整数拍和半拍起点，`1/4` 允许整数拍、半拍和四分之一拍起点；
对应最短间隔限制为 300 / 150 / 75 ms。按所选网格过滤原 MIDI 起音，不会把 offbeat 音符移到别的位置来改颜色，也不会在无音符的位置补点。
因此新生成的一拍版只显示白色音符，半拍版只显示白色和青色，四分之一拍版可出现黄色；紫色不会由这些规则生成。
长条尾部也向下收束到允许的网格位置，不会超过原 MIDI 持续时间和后续音符间距限制。
前奏和尾奏的辅助低音仍保持稀疏取样。更细网格通常更难，建议先尝试 `--grid 1/2`。
Swan song 种子 42（严格网格 v2）：一拍版 282 个头部，半拍版 539 个，四分之一拍版 856 个。
每种网格使用独立生成文件名，Shell 版本使用 `balanced-shell-v4` / `balanced-holds-shell-v4`，已有谱面不会被覆盖或自动更改。
要应用新规则，请重新执行随机生成命令；直接游玩旧 CSV 仍会显示旧谱面的全部拍位置。

v4 对自动选轨的简单模式（`grid 1`）增加稀疏段补点：基础谱面平均低于 1.5 个音符/秒，
且存在独立的 Piano 轨时，从该轨的真实整拍起音补点，优先拆分较长的空白，目标约 1.75 个音符/秒。
保留全部原有头部，继续遵守 300 ms 最短间隔；可用起音不足时不强行凑数。
补点与随机种子无关，手动指定 `--track` / `--support-track` 时使用原选轨规则。
半拍、四分之一拍模式保持原有抽取规则。
Petrichor 简单模式由 166 个头部增加到 **288 个**，约 **1.75 个/秒**，接近 Swan song 的 282 个、约 1.76 个/秒；
最长头部空白从 15.46 秒缩短到 4.42 秒。开启长条时，288 个头部中有 3 根长条。
主界面自动使用 v4；命令行可运行 `./random-play.sh songs/Petrichor.mid --seed 42 --grid 1 --holds`。

使用 `--holds` 后，生成器读取 MIDI note-off（含零力度 note-on）确定持续时间，
从同一起音处的持续音中选择长条。保持头部数量与起音时间不变，长条只替换部分单点：
数量上限为头部总数的 20%，两根长条至少相隔 5 个头部，最多一根同时进行，
长度至少一拍且不少于 400 ms，最多两拍；必要时缩短尾部，为后面的同手音符预留 300 ms。
未记录 note-off 的音符保持单点，不会根据音色或踏板混响猜测持续时间。
可用长音不足时，实际长条数量会低于上限，也可能为零。

同一 MIDI 和选轨设置下，含长条模式的头部数量、长条数量、首尾时间在不同种子之间完全相同，
仅随机变化四轨排列；没有同轨重叠。`--holds` 模式使用单独的文件名，不覆盖相同种子的旧单点谱面。
严格网格示例：Swan song 一拍版为 282 个头部、其中 8 根长条；Far in the blue sky 半拍版为 300 个头部、其中 6 根长条。
某首 MIDI 在粗网格上没有足够的起音或长音时，生成结果可能更稀疏，前奏和尾奏也可能留空。
颜色无需单独启用，游戏和编辑器自动根据整数拍、半拍、四分之一拍等起点位置着色。
长条仍采用前文说明的终端首尾两次按键判定。

程序优先自动选择名称包含 main/melody/lead 的旋律轨道，找不到时选择音符较多的非纯打击乐轨道；
自动选择 bass 轨道补充前奏和尾奏。可用 `--track N --support-track N` 指定轨道。
也可传入 `--fps 30`、`--offset 50` 或 `--silent`，含义与游戏相同。

默认将谱面保存在 `songs/generated/`，启动时打印**种子和完整路径**。生成的 CSV 可直接用游戏或编辑器打开。
种子同时记录在文件名和头部注释里；相同 MIDI、轨道及种子可复现相同谱面。
同一路径已有完全相同的谱面时复用；如果内容被手工修改则拒绝覆盖。
通过 `--output songs/mysong/random.csv` 可另选保存位置。
背景音乐继续复用 MIDI 的合成缓存，每次随机不会重新合成。

旧版生成的谱面仍可直接游玩。Shell 版本使用独立的 32 位随机算法，同一种子在新版本中可复现，但与旧 Python 版本的轨道排列不同；固定种子命令会按 v4 文件名另存谱面。

### MIDI 背景音乐和简单谱面导入

已经为你提供的 MIDI 制作了简单谱面：

```bash
./game.sh songs/far-in-the-blue-sky-easy/chart.csv
./editor.sh songs/far-in-the-blue-sky-easy/chart.csv
```

约 3 分 5 秒、148 BPM、268 个单点音符，无双押或长按。主段跟随主旋律，前奏与尾奏跟随稀疏低音节拍。
详情见 [歌曲说明](songs/far-in-the-blue-sky-easy/README.md)。

谱面中的 `# audio=` 或 `--audio FILE` 现在都可指向 `.mid` / `.midi`。
MIDI 包含音符与乐器指令，需要先合成为音频；首次播放使用 FluidSynth + GM SoundFont 离线生成 WAV，
并缓存在项目 `.cache/midi/`。后续使用缓存，MIDI 或音色库变化后会重新生成。
合成保留所有 MIDI 轨道；GM 音色可能与原作品的乐器音色不同。

MIDI 默认启用 `balanced` 音量增强：使用 FFmpeg 对安静段施加更多平滑增益，提升整体可听度，
再限制峰值。开头段也会增强；不会直接改写 MIDI 的力度或控制器数据。
增强在离线缓存中完成，补偿限幅器延迟并检查采样数、采样率与声道数，保持谱面对齐。
原始合成缓存仍保留，无需删除原缓存或重新生成谱面。

例如直接使用 Swan song：

```bash
./random-play.sh 'songs/Swan_song_–_Void.mid' --seed 42

# 按原始动态播放（不做音量增强）
RHYTHM_MIDI_LOUDNESS=original ./random-play.sh 'songs/Swan_song_–_Void.mid' --seed 42
```

可提前生成增强音频，或单独导出原始音量：

```bash
bash tools/midi_import.sh 'songs/Swan_song_–_Void.mid' --render-only --loudness balanced
bash tools/midi_import.sh 'songs/Swan_song_–_Void.mid' --render-only --loudness original
```

需要 FluidSynth、音色库和用于音量增强及采样时间校验的 FFmpeg / ffprobe（由 ffmpeg 包提供），常规安装方式：

```bash
sudo apt install fluidsynth timgm6mb-soundfont ffmpeg
```

本工作区还支持放在 `.cache/midi-tools/` 下的项目本地 FluidSynth 与 TimGM6mb 音色库。
可通过环境变量 `RHYTHM_SOUNDFONT=/path/to/font.sf2` 指定其他音色库。
缓存目录未纳入版本管理；复制项目到其他机器时，请重新安装上述依赖。

导入另一首 MIDI 的操作：

```bash
# 查看轨道编号、轨道名、音符数量、BPM 变化
bash tools/midi_import.sh 'songs/example.mid' --analyze

# 从选定旋律轨道生成简单单点谱面；可选低音轨道补前奏和尾奏
bash tools/midi_import.sh 'songs/example.mid' --track 1 --support-track 2 \
  --output songs/example-easy/chart.csv

# 生成带长条的固定谱面
bash tools/midi_import.sh 'songs/example.mid' --track 1 --holds \
  --output songs/example-holds/chart.csv

# 固定谱面也支持更细的抽取网格
bash tools/midi_import.sh 'songs/example.mid' --track 1 --grid 1/4 --holds \
  --output songs/example-quarter/chart.csv

# 预先合成背景音乐（也可直接游戏，首次播放会自动合成）
bash tools/midi_import.sh 'songs/example.mid' --render-only
```

导入器按原 MIDI 的速度图换算起音时间，默认每拍最多选一个旋律音符，音符间隔至少 300 ms；
`--grid 1/2`、`--grid 1/4` 可提高抽取密度，分别允许至少 150 / 75 ms 的间隔。
前奏/尾奏辅助轨道每两拍最多取一个音符。目标谱面已存在时拒绝覆盖，避免丢失手工编辑。
目前支持标准 MIDI format 0/1、PPQN 时间基准；生成谱面要求整数拍边界上的整数 BPM（20～400），
遇到不兼容的速度图会报错，避免编辑器显示错误拍数。仅作为 BGM 合成时不受该谱面格式限制。

### 音频文件

```bash
mkdir -p songs/mysong
# 先将自己的音乐文件放入 songs/mysong/music.ogg
./editor.sh songs/mysong/chart.csv --audio songs/mysong/music.ogg
# 编辑后按 E 保存，再开始游戏
./game.sh songs/mysong/chart.csv
```

也可以不指定音乐先编辑空谱面。`--audio` 会将指定音乐的绝对路径写入谱面；
如需移动或分享整个歌曲文件夹，可把谱面中的 `# audio=` 改为相对路径，例如 `music.ogg`。
编辑现有谱面时会自动读取音乐路径、BPM 和同步偏移。

编辑器使用时间网格，反色格子为光标，`[===]` 表示音符。`[~~~]` 表示该格附近存在未对齐当前网格的音符，
可用 N/P 精确选中。多个音符落在同一显示格时，用 N/P 逐个检查。

| 按键（小写，除特别说明） | 功能 |
| --- | --- |
| ↑ / ↓（兼容 W / S） | 光标时间向前 / 向后一个步长 |
| ← / →（兼容 A / D） | 光标移到左 / 右轨道 |
| N / P | 精确选取下一个 / 上一个音符，包含同时间的双押 |
| T | 切换毫秒网格 / 节拍网格 |
| F | 在光标的时间、轨道增加音符 |
| X | 删除光标所在的音符 |
| H / L | 将光标所在音符提前 / 延后一个步长 |
| U / I | 将光标所在音符移到左 / 右轨道 |
| V | 将选中起点的单点转换为一拍长条；再次按 V 转回单点 |
| J / K | 缩短 / 延长选中长条的尾部一个当前步长 |
| [ / ] | 减小 / 增大步长；节拍模式为四分之一拍、半拍、一拍 |
| B / b（区分大小写） | 在光标所在拍设置 BPM +1 / -1 的变速点 |
| C | 输入光标所在拍的 BPM，Enter 应用，Esc 取消 |
| R | 删除光标所在拍的变速点，继承前一段 BPM（第 1 拍不可删除） |
| O / o（区分大小写） | 同步偏移 +10 / -10 毫秒 |
| 空格 | 从光标位置试听 / 暂停 |
| E | 保存到当前 CSV 文件 |
| Q | 退出；有未保存修改时，再按一次 Q 放弃修改 |

例如：按 N 选中一个音符，H/L 调整其时间，U/I 调整轨道，E 保存。
最细步长为 **1 ms**；默认步长为四分之一拍（120 BPM 时为 125 ms）。
其他固定档位包括 5、10、25、50、100 ms，以及半拍和一拍。
毫秒模式的拍长步长按光标处生效的 BPM 计算。
移动到已有音符的位置会被拒绝，重复增加也不会生成重叠音符。

### 节拍网格和变速

按 **T** 切换为节拍网格，时间列显示拍数，每行右侧显示这一拍生效的 BPM。
第 **1 拍对应谱面时间 0 ms**；`5.000` 是第 5 拍，`5.500` 是第 5 拍之后半拍。
偏移量只影响与音乐的同步，不改变这里的拍数原点。

节拍模式默认 **一拍步长**，按 `[` 可依次切换到 **半拍、四分之一拍**，按 `]` 切回较大步长。
顶部 `Step` 显示当前值；每行网格也随之变成对应的拍间隔。
↑/↓、H/L、长条尾部 J/K 均按当前步长调整，最细为四分之一拍。
改变步长不会移动已有音符，也不会增加待保存修改；整数毫秒舍入不会让连续四分之一拍移动累计漂移。
移动跨过变速点时，会按完整 BPM 图换算，而不是固定加减某个毫秒数。
通过 N/P 选中不在整拍上的音符后，移动会保留拍内的小数位置；按 T 返回毫秒模式可继续精调。
长条移动时首尾一起移动；节拍模式和 BPM 编辑会同时换算起点和终点，保留首尾各自的拍位置。
长条需要选中起点才能编辑，使用 N/P 可精确选中。F 增加单点后按 V 即可创建长条，再用 J/K 调整长度。
节拍视图中的 `[~~~]` 表示该拍内存在非整拍音符；同一格内的多个音符可用 N/P 逐个选取。
切换显示本身不会移动音符，也不会产生待保存修改。

在目标拍上按 **C** 输入 BPM（20～400），即可创建或替换该拍的变速点；B/b 可以逐次增减。
如果光标位于非整拍，例如 `5.500`，修改会作用于它所属的**第 5 拍起点**。
BPM 从变速点开始生效，直到下一个变速点；显示的 `*` 标识显式变速点。
按 R 删除该点，让该段继承前面的 BPM；第 1 拍必须保留初始 BPM。

**编辑 BPM 会保留所有音符的拍位置，并重新计算它们的毫秒时间**，光标也随之更新。
例如初始 120 BPM，第 5 拍为 2000 ms；在第 5 拍设置 240 BPM 后，第 6 拍为 2250 ms。
将该点改成 60 BPM 后，第 6 拍的音符会移动到 3000 ms。
后续变速点仍保持原来的拍编号。保存仍使用整数毫秒，因此非整拍音符在变速重算时可能产生毫秒舍入误差。
如果重算造成同轨音符重叠或超出时间范围，本次 BPM 修改会被拒绝并保留原谱面。

试听时光标跟随音乐；按导航或编辑键会先暂停。再次按空格从当前光标开始播放。
更改音乐关联也算未保存修改。保存使用同目录临时文件再替换，减少中途写入导致损坏的可能。
Ctrl+C 直接退出，不会自动保存。

## 谱面格式和同步

```csv
# Four Keys chart v1
# audio=music.ogg
# offset_ms=0
# bpm=120
# tempo=5,240
2500,0
3000,1
3500,2
3500,3
4000,0,5500
```

每条数据为 `时间毫秒,轨道编号`，轨道为 0～3。相同时间不同轨道表示双押。
长条使用可选第三列：`起点毫秒,轨道编号,终点毫秒`，例如 `4000,0,5500`。
第三列是绝对终点时间，必须大于起点；单点继续使用两列，旧谱面可直接加载。
同轨长条区间内或结束时刻不能再放其他音符；加载、移动、调整长度与 BPM 重算都会检查冲突。
加载与保存会按时间、轨道排序并去重。支持空谱面编辑，游戏要求至少一个音符。
`# bpm=120` 指定第 1 拍的初始 BPM；可添加多条 `# tempo=拍编号,BPM`，例如
`# tempo=5,240` 表示从第 5 拍开始变成 240 BPM。拍编号必须是 2～9999999 的整数，
同一拍不能重复声明变速点；加载时会自动排序。没有 tempo 头部的旧谱面按固定 BPM 处理。
游戏使用保存后的毫秒时间判定，因此可直接游玩编辑器保存的变速谱面。
时间必须为 0～999999999 的整数毫秒；BPM 为 20～400，同步偏移为 -9999999～9999999 ms。
非空数据行必须符合示例格式；`#` 开头为注释。保存会重新生成标准头部，不保留自定义注释。

`audio` 相对于谱面目录解析，也可使用绝对路径。没有音乐头部的谱面可直接静音运行。
`offset_ms` 表示整体音符相对于音乐的延后量：**正值让音符更晚到达，负值更早**。
也可只对本轮覆盖音乐和偏移：

```bash
./game.sh songs/my-song/chart.csv --offset 50
./game.sh songs/my-song/chart.csv --audio /path/to/other.ogg
```

游戏中音乐同步采用异步查询，目标约每 50 ms 请求一次 mpv 播放位置，等待回复时继续读取和判定按键。
优先使用更频繁更新的 `audio-pts` 音频播放时钟，尚不可用时才回退到 `time-pos`。
终端输入模式和初始画面准备完成后才开始播放音乐。
回复携带采样时刻，中间用本地时钟推算，避免把播放器通信耗时加到按键误差中。
绘制和判定共用一个连续时钟：收到进度后逐步校正相位，校正速度上限为正常推进速度的 ±5%，
不会直接替换当前时间。孤立的大幅进度偏差先过滤，持续偏差才参与校正；
重复、未来或过于陈旧的采样会被忽略，避免一次异常响应让整张谱面突然下移。
显示前会再次采样同一个时钟，减少输入处理和帧构建开始时间之间的偏差。
未击中的音符到达判定线后，会保留显示到 140 ms 的判定窗口结束；判定窗口本身没有放宽。
音符位置直接由歌曲时间计算，游戏默认以 60 FPS 为目标绘制，编辑器保持约 30 FPS；
处理超时会跳过错过的帧，避免连续补帧。60 FPS 使用交替的毫秒截止时刻，避免取整造成累计漂移。
扩大下落区域后仍使用 2 秒下落时间，不改变音乐同步和判定窗口。实际绘制帧率受终端及机器性能限制。
编辑器静止时只在状态变化后重绘，试听时按固定节奏更新光标；只处理可见范围内的音符。
每帧逐行擦除旧内容，回到开头的空白区域不会保留之前的谱面。音频结束后继续推进时间，完成尾部判定。
音频卡住或进程退出会报错。终端、音频设备与按键传输仍会带来延迟，需要按实际手感调偏移。
播放期间请勿调整系统时间或缩小终端窗口。
播放器接口参考 [mpv 官方手册](https://mpv.io/manual/stable/#json-ipc)。
